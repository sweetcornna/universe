# ADR-0008 飞船：用方块拼装，服务端飞控，太空维度用真实坐标

- 状态：已采纳（组装、飞行、进出太空、降落卫星和母星、停船都在游戏里验证过）
- 日期：2026-10-17
- 取代：技术架构 §3.5 原来"实体加 GeckoLib 模型、跨维度先下船"的方案

## 背景

- 用户希望"自己做飞船飞行器，并且可以自定义加组件和外观"。GeckoLib 那样的固定模型只能换皮，做不到自己搭。
- M1 的原型 S4 要回答：载人的飞船怎样在星球和太空之间切换？高速飞行时区块加载的代价有多大？（路线图）
- 26.x 没有现成可用的"移动方块结构"模组（Valkyrien Skies、Create 的装置都还停在旧版本），也不想多一个依赖。

## 决定

### 方块拼装

- 飞船部件是普通方块：驾驶台、推进器（朝向就是喷口方向）、燃料舱（方块实体，存燃料）、脉冲引擎、座椅、16 色船体板。其他方块（原版的、别的模组的）也能装上去当船体，按质量分档：羊毛、地毯、玻璃和没有碰撞箱的方块算轻的。
- 在驾驶台上右键组装：从驾驶台出发，把连在一起的方块找出来（`core.ship.ShipAssembler`，上限 4096 个）。天然地形不会被带走（方块标签 `universe:ship_excluded`：泥土、沙、石头、矿石、树叶、冰雪……），基岩这类挖不动的、`BlockState#getRelocability` 说不能搬的方块也不要。床、门这种多方块结构只装进一半时拒绝组装（`BlockRelocability.Multiblock#isRelocatable`）；一艘船只能有一个驾驶台，至少要有一个推进器。
- 组装后方块从世界里移走（先拆方块实体，箱子不会把东西倒出来），变成一个实体 `universe:ship`。实体里存 `ShipStructure`：每个方块的局部坐标、方块状态和带 id 的完整方块实体数据，方向保持组装那一刻的世界方向，另记组装时驾驶台的朝向 `baseYaw`；画的时候整体转 `偏航 - baseYaw`。
- 性能在核心层算（`ShipStats`）：质量按部件累加（船体 1、推进器 2、燃料舱 1.5、脉冲引擎 4……吨），每个推进器 12 推力，每个燃料舱 2000 燃料，推重比按所在星球的重力算。HUD 和组装提示都显示推重比，推不动时提醒多装推进器。
- 燃料：给燃料舱喂发射燃料（1000）、煤、木炭、煤块、烈焰棒、岩浆桶。组装时把各舱的燃料加起来，停船时平均分回去。

### 飞行

- 飞控是核心层的 `ShipFlight`：有燃料时悬停；空格上升，速度按推重比减 1；Shift 下降；W/S 推进，A/D 转向，疾跑键加速。灵活程度按推力与质量之比，转向速度随质量变慢。没燃料就按重力往下掉。
- 服务端说了算：每刻读驾驶员的 `ServerPlayer#getLastClientInput()` 算速度和位置，客户端只做两刻的线性插值。驾驶员的 Shift 本来是下船，用 mixin 拦掉 `Player#wantsToStopRiding`；着陆后按住 Shift 一秒停船，乘客着陆后按 Shift 下船。
- 碰撞：船上每个露在外面的方块当一个碰撞箱，按轴分别扫过世界里的方块形状；转向前先检查转过去会不会嵌进地形。全是空气的区块段直接跳过。
- 停船：转到最近的 90° 倍数，方块按旋转后的朝向放回网格（不触发方块更新，放完再通知邻居），方块实体原样恢复。原地放不下就往上抬最多两格，再不行提示"这里放不下"。
- 客户端：船身用 `ModelBlockRenderer` 在一个只有船身方块的假世界里烘焙一次网格（剔面、环境光遮蔽、群系染色照常），每帧按朝向提交；箱子、告示牌、旗帜等走原版的方块实体渲染器。服务端只把 `getUpdateTag` 那部分方块实体数据发给客户端，箱子里有什么不发。推进器喷火冒烟，脉冲引擎喷蓝色焰流，引擎声随油门变化。骑上船自动切到第三人称，相机距离按船的大小拉远。

### 太空维度

- 每个恒星系一个太空维度 `universe:s<N>/space`：空的平坦生成器，黑色天空，没有时间线和云，高度 -256 到 256。
- 布局在核心层算（`core.space.SpaceLayout`）：恒星在原点，行星在 y = 0 的黄道面上按轨道相位摆开，轨道半径按对数压缩（`1500 + 3000·log2(1 + AU/0.25)` 格），相邻行星隔一两千格。每颗星球有一个"大气球"（半径 `60 + 50·星球半径`），卫星排在母星外侧。行星暂时不沿轨道移动。
- 进出：在星球上飞到维度顶部以上 48 格就进入太空，出现在大气球外、船头方向 24 格处；在太空里飞进大气球就进入那颗星球，从维度顶部以上 8 格开始降落。落点是上次从这颗星球起飞的位置（记在船上，也记在玩家的附加数据 `universe:departures` 上，停船后重新组装也记得）；没起飞过的星球按进入的方向换算到出生点周围 400 格内。气态巨行星和恒星把船推开并提示。
- 跨维度直接用 `Entity#teleport(TeleportTransition)`，26.x 会带着乘客一起走，不用先下船再上船。提示晚 5 刻再发，否则会被客户端的"按 Shift 下船"盖掉。
- 太空的天空：`PlanetSkyRenderer` 的太空模式在黑底星空上按真实距离画恒星和每颗星球的视大小，由远及近地画，恒星按距离插在中间，躲在恒星背后的星球不画。HUD 列出最近的三个天体：方位箭头、距离、能不能降落。脉冲引擎只在太空里能开，最快 40 格/刻，松开后两三秒内反推降回常规速度。
- 太空维度的区块不存盘（mixin `ChunkMap#save`），里面只有虚空，下次用到时重新生成；实体存在单独的文件里，不受影响。飞船在太空里被限制在维度底部以上 32 格到顶部以上 256 格之间，免得掉出世界。

## S4 的结论

- 采用方案 A（真实坐标）。在开发客户端（内置服务端，视距 12）测：太空里悬停 0.9 ms/刻；开脉冲引擎以 36–40 格/刻飞行时平均 5.4 ms/刻，P95 14.5 ms，P99 30.8 ms。单人够用，方案 B（浮动原点）先不做。
- 不拦区块存盘时，几次飞行就在太空维度写出 133 MB 的空区块，所以加了上面的 mixin。

## 理由

- 方块拼装让外观和配置完全由玩家决定，部件就是方块，配方、掉落、数据生成都走现成的流程；渲染复用原版的方块模型和方块实体渲染器，没有新依赖。
- 飞控、组装、性能、太空布局都在核心层，有单元测试（`ShipTest`、`SpaceLayoutTest`），换 MC 版本不受影响。
- 服务端权威的飞控不需要信任客户端发来的位置；代价是驾驶有一两刻的延迟，局域网里感觉不到。

## 后果

- 船是刚体，只有偏航，不会俯仰、翻滚；飞行中转到任意角度，停船时对齐到 90°。
- 船上的方块不工作：熔炉不烧、箱子飞行中打不开、红石不动；方块实体的动画（箱子盖）是静止的。船身按一个光照点取亮度。
- 其他实体不和飞船碰撞，飞行中不能在甲板上走动，乘客只能坐在座椅上。
- 太空里的行星不动，星球天空里的天体却按时间运行，两边对不上；以后让太空布局也按时间算。
- 已有存档里的太空区块文件（`dimensions/universe/s*/space/region`）可以直接删掉。
- 多人还没测过：多个驾驶员、远处玩家看到的插值、跨维度时的追踪。

## 备选方案

- **实体加 GeckoLib 固定模型**：做不到自己搭船，否决。
- **每刻真正移动方块**（类似 Create 的装置）：要不停地改区块，代价高、容易丢东西，否决。
- **移植物理船模组**（Valkyrien Skies 那样的子世界）：26.x 没有可用的版本，工作量远超 M2，否决。
- **方案 B 浮动原点**：等多人和更大的星系需要时再评估。
