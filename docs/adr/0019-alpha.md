# ADR-0019 Alpha：性能、兼容、多人和发布

- 状态：已采纳（随 M9 逐项实现）
- 日期：2026-10-20

## 背景

- 路线图的 M9：性能优化，兼容性测试（Sodium、Iris、JEI、Jade），多人测试，发布页、截图和文档，在 Modrinth 和 CurseForge 发布 Alpha。退出标准是公开发布 0.7 Alpha。
- 技术架构 §5 的性能预算：中等规模的基地（5,000 段传送带、500 台设备、同时加载 3 颗星球）保持 20 TPS，本模组每刻耗时低于 10 ms；完整显示戴森球时，中端显卡 1080p 帧率下降不超过 10%；第一次去一颗星球（含创建维度）等待不到 5 秒。
- 现状：
  - 没有自己的性能统计。传送带有一个核心层的基准（`BeltTest`，1 万段），设备、电网、物流、戴森球都没有在游戏里量过；也没有能一键搭出大基地的工具。
  - 没写过 GameTest。专用服务器从没启动过：`runServer` 要先同意 EULA，这得由作者本人决定。只在客户端用的代码有没有漏进公共代码，现在只靠写代码时注意。
  - 多人只在单人世界里验过，同步的包都是给一个玩家看的。
  - 兼容模组在 Modrinth 上都有 26.3 的 NeoForge 版本（2026-10-20 查）：JEI 31.16.0.86（测试版，maven.blamejared.com 上有 API 包），Jade 26.3.5，Sodium 0.9.2，Iris 1.11.7（要 Sodium）。REI 也有 26.3 的版本，EMI、WTHIT 没有。作者同意把这四个作为开发依赖下载。
  - `mod_version` 还是 0.1.0，`neoforge.mods.toml` 的描述是立项时写的。

## 决定

### 性能

- 自带分项计时：`/universe perf start` 开始记录，`/universe perf report` 列出每一项平均每刻多少毫秒和占服务器一刻的比例，`stop` 停止。不记录时只多一次布尔判断。分项是传送带、电网、物流、戴森球、各类设备（按方块实体类型分）、分拣器、海盗、小行星、蓝图放置、玩家每刻的处理（生存、外骨骼、兴趣点、守卫机、任务、驯养）。统计和排序放在核心层，有单元测试。
- 不依赖 Spark：分项计时只看本模组，Spark 看全局时作者自己装。
- 基准基地：`/universe bench <传送带段数> <设备台数>` 在玩家附近的空地上搭一片工厂：一圈圈装满物品的环形传送带，一排排在干活的制造台，用人造恒星和电力感应塔供电。搭好以后跑 `perf` 量。按预算的规模（5,000 段、500 台）量一次，再加上去两颗星球的情形。
- 优化按量出来的热点做，不预先改。目标就是 §5 的预算。

### 兼容

- JEI：写插件。每种设备配方一个分类（冶炼、制造、精炼、化工、粒子对撞），列出原料、产物、秒数和能做的设备；研究解锁的配方照样显示，界面上注明要哪个科技。工作台配方 JEI 本来就会显示。设备界面里点配方的箭头打开对应分类。
- Jade：写服务端数据提供者。设备显示进度、在做什么、缺电还是缺料；采矿机显示每分钟产量和剩余储量；发电设备显示功率；物流站显示每格的物品；射线接收站显示效率。
- 兼容代码放在 `compat` 包，对方模组存在时才加载，编译时只依赖对方的 API 包，发布的 jar 里不带它们。
- Sodium、Iris：不写代码依赖，只装上测。用 Gradle 属性 `-Pcompat=sodium`、`-Pcompat=iris` 决定开发客户端装不装，平时不装，免得影响别的无头验收。重点看自己画的东西：星球天空、戴森球、飞船和设备的模型、传送带上的物品、HUD。坏了再修。

### 多人

- 专用服务器：用 `gameTestServer` 启动（它跑完测试就退出，不走 EULA 流程；要是也要求同意 EULA，停下来问作者）。写几个 GameTest：制造台出产物、传送带送东西、电网分电、研究站加点。服务器能启动、测试能过，就说明公共代码没有引用客户端的类。
- 两个客户端：加一个运行配置 `client2`，游戏目录是 `run2`，用户名不同。第一个客户端用 `/publish` 开局域网，第二个直接连进来，两边都无头。看同步：别人放的设备和传送带、开飞船、戴森球、研究进度、交易、剧情广播、蓝图预览。

### 发布

- 版本号改成 0.7.0-alpha，`neoforge.mods.toml` 写上正式的描述、主页和问题反馈的地址、图标。
- 准备 Modrinth 和 CurseForge 的页面文字（中英文）、截图和更新日志，放在 `docs/release/`。上传要用作者的账号，由作者自己操作。
- 剧情文字还是占位，Alpha 的说明里写明。

## 理由

- 分项计时比 Spark 更合用：Spark 给的是方法栈，要从里面认出哪段是传送带；分项计时直接对应设计里的子系统，而且以后每次加功能都能拿基准基地复查。
- 基准基地用命令搭，不存一个测试存档：存档跟着版本和存档格式走，升级以后就打不开了；命令每次按当前的代码搭。
- JEI 是装的人最多的配方查看模组，REI 的玩家少得多；方块信息模组在 26.3 上只有 Jade。
- `gameTestServer` 能在不碰 EULA 的情况下验证专用服务器，GameTest 以后也能放进 CI。

## 后果

- 多两个可选的编译依赖（JEI API、Jade）。版本更新时，它们和 NeoForge 一起跟进；它们没出新版本时，兼容代码先关掉，不挡升级。
- 基准基地会在世界里放几万个方块，只给有权限的人用，最好在测试世界里用。
- 发布要作者的账号，最后一步不能自动完成。

## 备选方案

- 用 Spark 的 API 做统计：多一个依赖，而且 Spark 本身不一定先出 26.x 的版本。
- 同时做 REI 的插件：REI 有 26.3 的版本，但用户少，等有人要再做；EMI 没有 26.3 的版本。
- 用 `runServer` 测专用服务器：要先同意 EULA，那得作者本人决定；`gameTestServer` 已经够用。
