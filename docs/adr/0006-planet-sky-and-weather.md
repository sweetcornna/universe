# ADR-0006 星球天空、大气与天气：自定义天空渲染器、环境属性层、按维度的天气

- 状态：已采纳（M1 原型 S3 验证通过；开 Iris 的表现待测）
- 日期：2026-10-17

## 背景

- 每颗星球要看起来不一样：天色、雾、云、日落、水色随大气和配色变，天上能看到本星系的恒星、其他行星和卫星，天气也各有不同（游戏设计 §2.1）。
- 26.x 里天色、雾、云、星星亮度这些都成了环境属性，挂在维度类型、群系、时间线上。这三样都是登录时同步的注册表，运行时不能每颗星球加一份（ADR-0004）。S2 预置了 7 套维度类型（按昼夜长度和潮汐锁定区分）和 31 种群系，星球之间共用。
- 原版的天气是全服一份的 `WeatherData`，而每个能下雨的维度每刻都会推进一次计时，星球一多，主世界的天气就会乱；没有大气的卫星也会跟着下雪。

## 决定

### 天体在核心层算

- `core.sky.SkyModel` 按圆轨道算出某一时刻从观察者所在星球看到的每个天体：黄经、黄纬、显示用的视直径、亮面比例、距离、颜色。真实视大小在方块世界里看不见，显示时压缩（恒星几度，行星 1.5–4 度，从卫星上看母行星可达几十度）。
- `BodyLook`（派生键 `sky/look`）定每颗星球在别人天上的样子：表面类型（岩质、海洋、气态、冰、熔岩）、自转轴、自转周期、行星环。
- `StarField`（派生键 `sky/stars`）生成每个星系自己的星空和银河方向；`SkyColors` 由大气、配色、恒星算出正午晴天的天色、雾色、日落色、云量、日光颜色、水下雾色、白天能见的星星亮度、散射强度、大气雾距离。
- 这些都是纯 Java，有单元测试；命令 `/universe planet sky` 列出当前天上的天体，方便核对。

### 天空渲染器

- 7 套星球维度类型都带 `neoforge:custom_skybox = universe:planet`，同一个 `client.sky.PlanetSkyRenderer` 按当前星球画：天空底色、日出日落扇面、星空和银河、恒星、行星和卫星（从远到近）、地平线下的暗盘。
- 每帧的天体数据在 `ExtractLevelRenderStateEvent` 里算好挂到渲染状态上，渲染时只读。
- 自己的三条渲染管线（`SkyPipelines`）：星点（加亮混合）、恒星（加法混合，光晕按角度定大小，随散射强度变化）、行星（预乘透明度）。行星的相位、表面花纹、云层、大气边缘光、行星环和环上的阴影都在片元着色器里按参数程序生成，参数借 `DynamicTransforms` 的空位（`TextureMat`、`ModelOffset`、`ColorModulator`）传，不用贴图。
- 白天有大气时，行星的暗面不遮挡天光（降低遮挡度），其他行星在白天变淡；下雨和沙尘里天体隐去。

### 环境属性：插两层，不写数据包

- `mixin.EnvironmentAttributeSystemMixin` 在原版建环境属性系统时插进两层（`world.planet.PlanetEnvironment`）：
  - 底色层：在维度、群系之后，时间线、天气之前，换成这颗星球正午晴天的值（天色、雾色、云色和云量、日光颜色、水下雾色、星星亮度下限、浓密大气的雾距离、高温星球上水会蒸发）。入夜变暗、下雨变灰仍由原版的时间线和天气叠加在上面，昼夜长度不同的星球不用另写。
  - 收尾层：在时间线、天气之后，给日出日落光晕换颜色、按大气调强度；沙尘一类天气压掉日落和星星。
- 服务端和客户端都建这两层：视觉属性只有客户端用，玩法属性（水会不会蒸发）两边要一致。
- 水色：流体的染色走 `ClientLevel.calculateBlockTint`，`mixin.client.ClientLevelMixin` 对水的染色器返回星球液体的颜色（必须是不透明的 ARGB，透明度为 0 时水直接看不见）。

### 每颗星球自己的天气

- `mixin.ServerLevelMixin` 把星球维度的 `advanceWeatherCycle` 换成 `world.planet.PlanetWeather#tick`：按星球的 `WeatherProfile` 轮换晴天、普通天气、风暴，状态存在维度自己的 `SavedData`（`universe:planet_weather`）里。主世界和其他原版维度照旧。
- 平均晴雨时长由频率定（`core.weather.WeatherCycle`，有单元测试）：天气占的时间比例约等于频率，每段持续时间随机。没有大气或频率极低的星球永远晴天。
- 雨、雪、酸雨设置这个维度自己的降雨、雷暴强度，像原版一样广播给这个维度里的玩家，由原版画雨雪、积雪、熄火、打雷。
- 沙尘、火山灰、晶尘不能算下雨（否则会熄火、积雪），强度用 `PlanetWeatherPayload` 单独同步。客户端由 `ClientWeather` 平滑过渡，交给环境属性层把天色、雾色拉向风暴颜色、把雾拉近（最浓时 36 格），再在玩家周围生成随风飘的粒子。
- 原版 `/weather` 只管主世界；星球用 `/universe planet weather clear|normal|storm [秒]`。

## 理由

- 环境属性系统本来就是分层求值的，插层只改"这颗星球的底色"，原版的昼夜、天气、时间线逻辑全部保留；比每颗星球生成维度类型或群系简单，也不受同步注册表的限制。NeoForge 没有给这个构建过程开事件，只能用 mixin，注入点只有两个、都在构建器末尾，跟版本的风险小。
- 天体参数和配色都在核心层，渲染器只是"按参数画"，换 MC 版本时只动渲染器；着色器程序生成表面，上百颗星球不用一张贴图。
- 天气按维度分开存，和原版的全局天气互不干扰；仍然复用原版的雨雪渲染和玩法效果。

## 后果

- 依赖 Mixin：`universe.mixins.json`，在 `neoforge.mods.toml` 里登记。26.x 运行时就是官方名，不需要 refmap。注入点：`EnvironmentAttributeSystem#addStaticLayers`、`#addDynamicLayers`、`ServerLevel#advanceWeatherCycle`、`ClientLevel#calculateBlockTint`。升级 MC 时要先核对这几个方法的签名，`defaultRequire = 1`，对不上会在启动时报错，不会悄悄失效。
- `SkyColors`、`BodyLook`、`StarField` 用了新的派生键，属于存档格式。
- 网络协议版本升到 3。
- 测试时注意：玩家身上有夜视效果时，原版会把雾色按最亮通道拉满，雾看起来会亮很多（踩过）。
- 还没做：
  - 酸雨仍按普通的雨画，没有单独的颜色和腐蚀效果；
  - 戴森云和戴森球（M6）；
  - 开 Iris 光影时的表现：Iris 会接管天空渲染，需要实测，必要时给光影包提供简化的天空。

## 备选方案

- 每颗星球生成一份维度类型或群系：要在登录时同步注册表，运行时新发现的星球进不去（ADR-0004 已排除）。
- 在 `ComputeFogColor` 等客户端事件里改颜色：只能改雾，天色、云、星星亮度、日落颜色、水下雾色没有对应事件，服务端的玩法属性也改不了。
- 天体用贴图：每颗星球一张，要么预置有限几套，要么运行时生成纹理。程序化着色器更省事，也能做相位、自转和环的阴影。
- 沿用原版全局天气：所有星球同时下雨，没有大气的卫星也下雪，不能接受。
