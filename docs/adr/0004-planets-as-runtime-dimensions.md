# ADR-0004 每颗星球是一个运行时创建的维度

- 状态：提议（M1 验证后定稿）
- 日期：2026-10-16

## 背景

- 每颗星球需要独立的地形生成器、天空和环境、世界边界、重力等。
- 星团里有上百颗星球，但玩家只会去其中一部分。
- 原版的维度在数据包里定义，服务器启动时加载，不支持运行时新增。

## 决定（提议）

- 每颗可登陆的星球对应一个维度，第一次有玩家前往时在运行时创建。
- 已创建的星球列表存进 SavedData，服务器启动时重新创建。
- 长时间没有玩家、也没有强制加载区块的星球维度会被卸载。
- 维度类型、群系、时间线等同步注册表在运行时无法新增，因此预置有限的环境模板供星球挑选；星球之间的细节差异由参数化生成和客户端渲染体现（见[技术架构](../02-architecture.md) §3.2–3.4）。
- 每个恒星系另有一个太空维度，同样按需创建。

## 待 M1 验证

- 创建、卸载、重启恢复是否稳定，有没有内存泄漏。
- 客户端的维度列表能否正确同步（传送、重生点、命令补全）。
- 和其他模组的兼容，例如地图、小地图类模组对新维度的处理。
- 每个维度的内存占用。

## 参考

- [Infiniverse](https://github.com/Commoble/infiniverse)（Commoble，MIT 许可）：运行时创建和移除维度的库，主分支仍在维护，是否已支持 26.3 待确认。

## 备选方案

- **A 预建维度池**：服务器启动时建好 N 个空维度，按需分配给星球。实现简单，但数量有上限，启动开销也大。如果运行时维度在 M1 验证失败，就退回这个方案。
- **B 单维度分区**：把多颗星球放进同一个维度的不同区域，从而避开运行时维度。但天空、天气、重力、昼夜要按区域切换，很别扭，也和其他模组对"维度"的假设冲突。
