# ADR-0001 目标版本：跟随最新正式版

- 状态：已采纳
- 日期：2026-10-16
- 当前版本：Minecraft 26.3 + NeoForge 26.3.0.86（Java 25）

## 背景

2026 年 10 月可选的版本（NeoForge 正式版的最新构建）：

| Minecraft | NeoForge | 情况 |
|---|---|---|
| 1.21.1 | 21.1.262 | NeoForge 上最流行的版本；作者的整合包 Essence Odyssey 在用 |
| 26.1.2 | 26.1.2.122 | NeoForge 26.1 发布公告的作者推测它可能成为下一个主流稳定版本 |
| 26.2 | 26.2.0.93 | |
| 26.3 | 26.3.0.86 | 最新正式版，NeoForge 于 10 月 11 日前后转为正式版 |

本项目预计要开发一年以上，作者希望模组适配最高版本。

## 决定

只以当前最新的 Minecraft 正式版为开发目标，现在是 26.3。新版本的 NeoForge 正式版发布后 2–4 周内跟进，不同时维护多个 Minecraft 版本。

## 理由

- 符合"适配最高版本"的目标，等到正式发布时，26.x 的生态也会更成熟。
- 26.x 取消了混淆，读源码、跟版本都更容易。
- 关键依赖已有 26.3 版本：GeckoLib、JEI、Jade、Curios，以及用于兼容测试的 Sodium、Iris。
- 1.0 之前没有玩家存档的包袱，现在升级成本最低。

## 后果

- 每次升级都要处理 API 变化，所以核心逻辑必须和 MC 解耦（[ADR-0003](0003-core-decoupling.md)）。
- 不能直接放进 1.21.1 的整合包，包括 Essence Odyssey 的当前版本。
- 资料和示例比 1.21.1 少，写代码前要先查源码和文档。

## 升级步骤

1. 确认新版本的 NeoForge 已有正式版（版本号不带 `-beta`），用到的依赖也都有对应版本。
2. 对照 [NeoForgeMDKs](https://github.com/NeoForgeMDKs) 里对应版本的 MDK，更新 `gradle.properties`、`build.gradle` 和 Gradle wrapper。
3. 阅读 NeoForge 的发布公告和原版的变更说明，修复编译错误。
4. 跑单元测试、GameTest，再用固定种子的测试世界手动走一遍。
5. 更新本 ADR 的"当前版本"、`CLAUDE.md` 和 `README.md`。

## 何时重新评估

1.0 发布前，如果社区明显集中到某个版本（比如 26.1.x 成为长期版本），考虑停在那个版本，或者用 Stonecutter 一类的工具同时构建多个版本。

## 备选方案

- **1.21.1**：生态最成熟、资料最多，也能直接放进 Essence Odyssey；但与"适配最高版本"的目标相反，以后迁移到 26.x 的成本很高（渲染、物品模型等都改过）。
- **26.1.2**：可能成为长期版本；但不是最新版，作者希望适配最高版本。
