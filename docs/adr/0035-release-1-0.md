# ADR-0035 1.0：发布前的检查、存档的承诺和版本号

- 状态：已采纳（发布由作者确认）
- 日期：2026-10-24
- 相关：ADR-0019（Alpha）、ADR-0032（1.0 放在 M19 之后）、ADR-0033、ADR-0034

## 背景

- M19 在 2026-10-24 做完。ADR-0032 定了 M19 之后就是 1.0。公开过的只有 0.14.0-alpha（2026-10-23）；之后的 M17 音效和材质、M18、M19 都还没发。
- 0.14.0-alpha 发布说明里的已知问题：`/universe` 调试命令的反馈只有中文；跨恒星系的跃迁运输只有单元测试；专用服务器没长时间开过；还没有人从头到尾完整玩过一遍；剧情文字是占位稿；开光影包时本模组维度的天空不对。
- Java 代码从 0.14.0-alpha 的 15.8 万行涨到 20.7 万行。新功能都在开发客户端和 GameTest 里验过，但没有按多人、存档、专用服务器这几个方向整体查过。
- CI 只跑 `./gradlew build`（单元测试）。159 个 GameTest 只在本机跑；改了数据生成却忘了提交 `src/generated`，CI 也查不出来。

## 决定

### 版本号

- 叫 1.0.0，GitHub Release 不再标 pre-release。以后的修补按 1.0.x，加内容按 1.x（M20 化学与生物研究是 1.1）。

### 发布前要做完的

1. 调试命令的反馈改成语言键，中英文都有。
2. CI 加两步：跑一遍 `runData`，`src/generated` 有变化就失败；跑全部 GameTest。失败时把 `run/logs` 和崩溃报告传上来。
3. 跨恒星系的物流在 GameTest 里完整跑一趟：派船、扣翘曲器和电、跃迁过去、卸货、空船回来，反方向取货也跑一趟。
4. 按三个方向查 0.14.0-alpha 以来的代码，每个方向一个人找、另一个人反驳，留下来的问题全部修掉：
   - 存档：0.14.0-alpha 的存档在 1.0 里打开会不会崩、丢数据、进度归零；
   - 多人：客户端发来的包服务端信不信得过，有没有刷物品、远程改别人东西的路子，客户端看到的状态有没有同步；
   - 专用服务器：世界生成的线程碰共享状态、主线程同步加载区块、按玩家记的表不清理、会让服务器这一刻崩掉的异常。
5. 拿 0.14.0-alpha 的专用服务器造一个存档（研究、信用点、戴森球、黑雾基地、参照基地、去过几颗星球和太空），用 1.0 的专用服务器打开，客户端连上去转一圈，再挂着跑半小时以上，看日志和分项计时。

### 存档的承诺

- 从 1.0.0 起，1.x 都能读之前 1.x 和 0.14.0-alpha 的存档。
- 为此写代码时守这几条：新存的字段一律可选、带默认值（`optionalFieldOf`，方块实体和实体按可选读）；注册名不删不改，要改就加别名；存档里的枚举按名字存，或者只往后加；`core.procgen.Seeds` 的派生结果不动。改了存档格式的版本，更新日志里写"存档"一节，说清老存档读进来是什么样。
- 网络协议变了照旧要求客户端和服务端一起更新，版本对不上的客户端在连接时就会被 NeoForge 拒掉。

### 还留着的已知问题

- 剧情文字是占位稿，要和作者单独商量方向和文风再重写（路线图 M8）。
- 开光影包时本模组的星球和太空用的是光影包的主世界天空，要光影包那边支持（ADR-0019）。
- 每一段都验过，但还没有人从头到尾完整玩过一遍，数值和节奏可能还要调。这条照实写进发布说明。
- Modrinth 和 CurseForge 上架要作者的账号，图库按 `docs/release/page.md` 的表重截，都由作者操作。

## 备选

- 叫 1.0.0-beta：理由是没有人完整玩过一遍。但各系统都在游戏里验过，发布前又查了一轮，没玩通这件事写进已知问题就够了。叫 beta 也不会改变接下来要做的事，修补照样按 1.0.x 出。
- 等剧情定稿再发 1.0：剧情要和作者单独商量，时间定不下来；玩法已经齐了，剧情改好以后放进 1.x。
- 不查代码，直接发：0.14.0-alpha 以来新写的代码占了现在的四分之一，又是第一次承诺存档兼容，值得在发布前花一轮查。

## 结果

2026-10-24 五项检查做完，发布等作者确认。

- 调试命令：14 个命令类的反馈改成语言键，补了 174 条中英文。
- CI：`.github/workflows/build.yml` 加了数据生成检查和 GameTest 两步。
- 跨恒星系物流：`InterstellarTripGameTests` 送货、取货各跑一整趟，没查出代码的问题。
- 查代码：第一轮三个方向确认了 11 个问题，1 个能刷物品，3 个该修，7 个小问题，全部修掉。修完的提交再交给别人复查，第二轮又找出 10 个，其中货舱就地改的东西不写回船上能刷物品，0.14.0-alpha 里就有；第三轮找出 4 个，外加两个机器一忙就偶尔失败的 GameTest。每个修正都配了 GameTest，并且确认去掉修正时测试会失败。
- 存档和长跑：0.14.0-alpha 的专用服务器造的存档在 1.0 里打开，信用点、105 项研究、戴森球的轨道、太阳帆和层、黑雾基地、剧情进度和维度都在。参照基地（5000 条传送带、500 台装配机、500 个分拣器）挂着跑 36000 刻，服务器每刻 5.57 ms，本模组占 1.01 ms，一次"Can't keep up"也没有，没人的运行时维度会自己卸掉。客户端日志里酸液缺方块模型的警告顺手补上了。
- 发布时：1070 个单元测试、193 个 GameTest 全过，GameTest 连跑三遍没有偶发的失败。
- 留到以后：几个聚落和太空的 GameTest 按刻数等后台加载区块，CI 的机器上可能偶尔超时，要照 `far_chunks_load_in_background` 改成按真实时间限时（见 `docs/02-architecture.md` 的 26.x 表）。
