# ADR-0003 纯 Java 核心与游戏适配层分离

- 状态：已采纳
- 日期：2026-10-16

## 背景

- 跟随最新版（[ADR-0001](0001-target-version.md)）意味着 Minecraft 和 NeoForge 的 API 会经常变化。
- 工厂模拟、程序生成、戴森球计算是逻辑最复杂的部分，需要可靠的测试，而在游戏里测试很慢。

## 决定

- 不依赖游戏的逻辑放在 `io.github.sweetcornna.universe.core` 及其子包，禁止 import `net.minecraft`、`com.mojang`、`net.neoforged`。
- `CoreIsolationTest` 在每次构建时检查这条规则。
- 适配层（方块实体、实体、维度等）只做数据转换和事件转发，具体逻辑交给 core。
- 暂时不拆成独立的 Gradle 子项目。等到需要同时构建多个 MC 版本时，再把 core 提取成子项目。

## 理由

- core 的逻辑可以用 JUnit 测试，毫秒级完成，CI 上也能跑。
- 升级 MC 版本时 core 基本不用改，改动集中在适配层。
- 边界清楚，多人或 AI 助手参与开发时不容易把代码写乱。

## 后果

- 适配层要写一些转换代码，比如方块坐标和 core 自己的坐标类型互转。
- core 里不能用 MC 自带的工具类（如 `Mth`、`RandomSource`），要自己实现或用 JDK 提供的。
- 检查只看 import 语句；在代码里写完整类名绕过检查的做法同样禁止，靠代码审查把关。

## 备选方案

- **不分层**：前期写起来快，但测试和升级成本都高。
- **拆成 Gradle 子项目**：用编译期依赖强制隔离，但目前构建上的复杂度大于收益。
