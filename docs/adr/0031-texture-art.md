# ADR-0031 材质：商业像素游戏的水准

- 状态：已采纳（M17）
- 日期：2026-10-23

## 背景

- 用户 2026-10-23："完成度要极高，要复刻戴森球和无人深空玩法，并且材质要细腻，达到商业化像素游戏标准"。
- 现状：模组有 904 张贴图（方块 578、物品 237、实体 79、界面 10），全是 M1 以来各里程碑写的 55 个 Python 脚本（`tools/*_textures.py`）画的。画法是"底色乘一个系数"加逐像素的随机噪点：
  - 每个脚本自己定 RGB，没有共用的调色板，各里程碑的颜色对不齐。
  - 设备的正面是大片平涂，细节小而稀；光照方向各画各的。
  - 物品用接近纯黑的一圈描边，里面平涂，没有体积。
  - 和原版方块摆在一起，一眼看得出是程序画的。原版 1.14 以前的贴图被叫作"程序员美术"（programmer art），1.14 起换成 Jappa 画的、照传统像素画规矩画的一套，我们现在的水平接近前者。
- 参考：
  - Faithful 材质包把 Jappa 的画法整理成了规矩（[f32 texturing guidelines](https://docs.faithfulpack.net/pages/textures/f32-texturing-guidelines)、[Classic Faithful 32x guidelines](https://docs.faithfulpack.net/pages/textures/cf32-texturing-guidelines)）：先定材质（粗糙还是光滑、亮面还是哑光）再定画法；一张图的颜色少而精，最亮和最暗的颜色之间要有过渡色；色带收窄到一两个像素；不要大片平涂；滤镜生成的噪点只在材质需要时留；描边和分隔线一个像素宽；远看和原版比。粗糙的材质（石头、沙子、锈）多用抖动，光滑的金属少过渡、对比强，宝石只用抗锯齿。
  - Slynyrd 的 [Pixelblog #1 调色板](https://www.slynyrd.com/blog/2018/1/10/pixelblog-1-color-palettes)：色阶要偏色相，越亮彩度越低，暗部彩度高；不偏色相的色阶又平又闷。
  - Lospec 的[选择性描边](https://lospec.com/articles/pixel-art-outlines-part-2-using-color)：描边用相邻颜色的暗色，受光处浅、背光处深，不用一圈纯黑。
- 像素密度：商业像素游戏绝不在同一画面里混用不同的像素大小（Faithful 叫它 mixel）。原版一格方块是 16 像素，模组的方块、物品要是 32 像素，和原版、和别的模组摆在一起就是混像素。

## 决定

### 一、分辨率不变，靠画法变细腻

- 方块、物品 16×16；实体按一格 16 像素的密度；界面照原版的比例。
- "细腻"靠色阶、光影、材质表现、构图，不靠加像素。

### 二、一套调色板

- 全模组共用 `tools/pixel/palette.py`：每种材质一条 5–8 级的色阶，在 OKLCH 里生成（`tools/pixel/color.py`）。
  - 暗部往冷色（蓝紫，268°）偏，亮部往暖色（黄，82°）偏，像日光加天空的环境光。
  - 彩度在中间偏暗处最高，往两头收。
  - 最暗的一级亮度不低于 0.18（不出纯黑），最亮不高于 0.97（不出纯白）。
- 现有的色阶：钢（机壳）、石墨（框架、深色件）、白漆、铁、钛、铜、黄铜、金箔、橡胶、混凝土；琥珀、警示黄、红、绿、青、蓝、紫；玻璃、屏幕；青、琥珀、绿、红、紫、白六种发光。
- 贴图只从色阶里取色，不在脚本里临时写 RGB。新材质先加一条色阶，在 `build/texture-preview/_palette.png` 里和别的比过再用。
- 等级色：Mk.I 琥珀、Mk.II 绿、Mk.III 蓝。运转的指示灯是青色，和界面一个颜色。

### 三、画法

- 光从左上来。凸起的东西上边、左边亮一级，下边、右边暗一级；凹进去的反过来。圆柱的亮带偏向受光的一侧，背光的边最暗。
- 画布（`tools/pixel/canvas.py`）里每个像素记"哪条色阶、第几级"，倒角、阴影、高光都是加减级数，最后统一换成颜色。
- 设备的面：
  - 凸起的钢框：最外一圈暗，让相邻的方块分得开但不成黑网格；里面一圈上左亮、下右暗；框里的面板稍凹。
  - 面板从左上到右下亮一级到暗一级，交界错开几个像素，不拉成直线。拉丝纹理两三个像素一团，不用逐像素的噪点。
  - 框边偶尔掉漆（亮一级），面板下部积一点灰（暗一级）。
  - 正面是认得出的功能区（观察窗里的机械臂、炉口、屏幕、风扇），顶上一排状态灯，下面一条等级色。
- 物品：小东西一个像素一个像素地画（`Canvas.draw`，网格里一个字符是一条色阶的一级），四到六级明暗，占满 12–14 个像素。描边用这块材质自己最深的一级，受光的左、上边浅一级，不用纯黑。金属点一两个高光，晶体分出受光面、正面、背光面三个切面。
- 抖动只用在粗糙的材质上（岩石、沙土、锈），用有序抖动；金属、玻璃、塑料不抖动。
- 发光：灯、屏幕、工作灯用发光色阶。标了发光的配方另写一张 `<名字>_glow.png`，只含发光像素；设备运转时模型（`models/block/machine_glow.json`）在正面叠一层共面的元素贴这张图，`light_emission` 15、不受方向明暗。夜里灯和屏幕是亮的，别的地方照常变暗。数据生成时看这张图在不在，自动换模型；顶面也亮的设备再有 `<名字>_top_on_glow.png` 就换成 `machine_glow_top.json`，正面、顶面各叠一层。实体的 `_glow` 贴图也这样从同一个配方里分出来。
- 半透明（玻璃、液体、光晕）：画布的像素可以带不透明度，其余一律不透明。
- 染色的贴图（星球方块、植物的底层）在游戏里按星球配色逐通道相乘，只用灰度色阶 `gray` 画，平均亮度 0.8 左右，不然配色会被压黑。
- 动画贴图的帧从上往下排成一长条，帧数和原来一样，`.png.mcmeta` 不动。
- 实体贴图的 UV 布局不变：每个方块盒子占的区域照模型代码（`LayerDefinition` 里的 `texOffs` 和盒子尺寸）画，模型不动。

### 四、工具和检查

- `tools/pixel/`：颜色和色阶（`color.py`）、调色板（`palette.py`）、画布（`canvas.py`）、自动检查（`lint.py`）、总览图（`preview.py`）。
- `tools/textures/`：配方，一个函数画一张图（`recipe.py` 登记），一组贴图一个模块；几组共用的部件（机壳、螺栓、状态灯、风扇、等级色）在 `parts.py`。`build.py` 渲染、检查、写文件、出总览图：

  ```
  uv run --no-project --with pillow python tools/textures/build.py <模块|all> [--only 路径 ...] [--no-write]
  uv run --no-project --with pillow python tools/textures/build.py all --coverage
  ```

  `--coverage` 列出贴图目录里还没有配方的图。同一张图只能由一个模块画，重了就报错。

- 自动检查：方块不超过 14 种颜色、物品 16 种（发光色不算）；没有接近纯黑、纯白的颜色；明暗跨度够大；零碎的孤立像素不超过一成（粗糙材质两成，手绘的像素不算）；染色的贴图没有彩色、平均亮度在 0.66–0.90；尺寸和原来的一样；动画按帧分开查。检查只提示，不拦着写文件。
- 总览图 `build/texture-preview/<模块>.png`：每行是提交里的旧图、新图、新图 3×3 平铺（看接缝和重复；动画换成前几帧），最下面是原版的参照（直接从 Minecraft 的 jar 里读，不进仓库）。
- 游戏里看：开发脚本在测试世界搭一面墙，新贴图的方块和原版的熔炉、高炉、铁块摆一排，物品放进展示框和原版物品挨着，白天、斜看、近看、夜里各截一张。

### 五、范围和顺序

- 全部重画，按题材分组：工业设备，高级设备和戴森球，物流，中间产品，防御设施，飞船和空间站，装备和载具，敌对生物和 NPC，星球的植物，星球的地形、矿物和兴趣点，食物。镜头光晕、星光这些平滑的光斑（`gui/flare/*`、`gui/disc`、`gui/ring`、`gui/star_glow`）不是像素画，保留原来的生成方式。
- 先做一组样板（装配机四个面、通用机壳顶、四个物品）定下样子，再按组分给子代理并行画；全部有了配方、在游戏里看过之后，再删掉旧脚本。
- 实体贴图要保持原来的 UV 布局，模型不动。

## 后果

- 贴图整套能重新生成，换一条色阶就整体换色。
- 发光层让运转中的设备在夜里看得见状态，多了一个共面的元素，开销很小。
- 原版没有、我们也不做的：高分辨率材质包、法线贴图和高光贴图（要光影模组）。
- 旧脚本随着重画逐个删掉；在重画完之前，两套脚本会同时存在，同一张图只能由一边生成。

## 备选方案

- 32×32 或更高：和原版、和别的模组混像素，工作量是四倍。不用。
- 请美术在绘图软件里手画：没有人手；网格里逐个写像素和手画是一回事，而且能统一调色板、能重新生成。
- 在旧脚本上调参数：没有共用的调色板和光照模型，调不到这个水准。
- 拿原版贴图改色：原版贴图是 Mojang 的，不能随模组分发；立项书也要求原创。
