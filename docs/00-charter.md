# Universe · 寰宇：项目立项书

> 版本 0.1 · 2026-10-16 · 当前阶段：M0 立项
> 负责人：sweetcornna
> 中文名"寰宇"为暂定名

## 1. 一句话概述

从方块世界出发，驾驶飞船探索程序生成的星系，建设跨星球的自动化工业，最终在恒星周围建造戴森球。

Universe 是一个 Minecraft Java 版模组（NeoForge），用一条成长线把三种体验串起来：

- 方块建造和生存来自 Minecraft，是成长线的起点。
- 探索学无人深空（No Man's Sky）：程序生成的星系和星球，各有生态和环境危害，配合飞船、外骨骼和多功能工具。
- 工业学戴森球计划（Dyson Sphere Program）：传送带、分拣器、电网、科研矩阵、行星内和星际物流，终局目标是戴森球。

## 2. 背景与机会

### 2.1 为什么做

- 三者的乐趣互补。MC 提供自由建造和生存，无人深空提供"下一颗星球会是什么样"的好奇心，戴森球计划提供把一切自动化、越建越大的工程成就感。目前 MC 生态里还没有模组把三者做成一条连贯的成长线。
- 26.x 版本周期刚开始。Mojang 取消了代码混淆，NeoForge 的 26.x 生态正在成形，新版本上的大型内容模组还不多，先到的模组更容易被整合包采用。
- 作者做过整合包 Essence Odyssey（本源远征）的设计和发布，熟悉 NeoForge 生态，也了解科技向玩家的需求。

### 2.2 同类模组（2026-10 检索）

| 模组 | 方向 | 和本项目的区别 |
|---|---|---|
| Ad Astra / Stellaris | 火箭、太阳系内的固定星球 | 星球是手工设计的固定几颗，没有程序化宇宙，工业要靠别的模组 |
| No Man's Craft | 程序化星球和群系（依赖 Stellaris，1.21.1） | 仍在 Alpha，重心是地形，没有工业和戴森球 |
| Genesis | 基于 Valkyrien Skies 的太空飞行 | 方块拼装的物理飞船，玩法重心不同 |
| The Dyson Sphere Project | 把戴森球作为自动化终局（1.20.1 Forge） | 只有戴森球这一个目标，没有探索 |
| Dyson Sphere Energy Mod | 太阳帆、射线接收站发电（1.21.1） | 只做发电机制 |
| Create、Mekanism 等 | 通用工业 | 成熟但没有星际维度；本模组通过 NeoForge 的通用接口和它们互通 |

同时做程序化星系、星际工业和戴森球的模组，MC 里还没有先例，26.x 上也没有。

> 以上信息来自 Modrinth、CurseForge 等公开页面，各模组的版本支持情况可能已有变化。

### 2.3 目标玩家

- 玩过戴森球计划、异星工厂（Factorio）、幸福工厂（Satisfactory），喜欢科技向整合包的玩家；
- 喜欢探索、收集、看风景的玩家；
- 整合包作者，包括 Essence Odyssey 的后续版本。

## 3. 设计支柱

1. 方块为本：建造始终用方块完成。主世界就是母星，原版资源在前期一直有用。不把 MC 改成另一款游戏。
2. 星球探索：每颗星球都有自己的环境、危害、资源和景观，玩家想知道下一颗星球是什么样，于是继续往前走。
3. 星际工业：资源分散在不同星球和恒星系，想扩大规模就得靠自动化和物流。成就感主要来自产线越建越大。
4. 戴森球：看得见的长期目标，在天空里一点点成形，建成后又为终局科技供能。

## 4. 目标与非目标

### 4.1 1.0 版目标

- 由世界种子决定、可以复现的星团：几十个恒星系、上百颗可登陆星球，玩家到访时才生成。
- 完整的成长线：原版生存 → 电磁工业 → 首次离开母星 → 行星际物流 → 星际跃迁 → 戴森球 → 宇宙矩阵。
- 飞船：起飞、太空飞行、着陆、跃迁的完整流程，多人可以同时在太空中。
- 星球生存：外骨骼、生命维持、温度/毒性/辐射危害，多功能工具（采矿、扫描、分析）。
- 工业：戴森球计划风格的传送带、分拣器、电网、生产设备、科研矩阵、物流站。数千段传送带的规模下保持 20 TPS。
- 戴森云与戴森球：发射、建造、在天空中实时可见，通过射线接收站供能。
- 多人可用：服务端权威，新增的状态都能同步和存档。
- 和常见模组互通：使用 NeoForge 的物品、流体、能量传输接口，提供 JEI 配方和 Jade 信息显示。

### 4.2 非目标（1.0 不做）

- 不做 Fabric 版，不移植到 1.21.1 等旧版本。
- 不做球形星球地表。地表仍是有边界的平面世界，球形只体现在太空里看到的外观。
- 不做方块拼装的物理飞船（Valkyrien Skies 那一类）。飞船是预制模型，可以模块化改装。
- 不做 NPC 文明、贸易经济、星际战争。星球守卫之类的战斗内容放到 1.0 之后再考虑。
  - 2026-10-17 修订（[ADR-0013](adr/0013-dsp-and-nms-core-loops.md)）：空间站贸易、守卫机和海盗的战斗进入范围；NPC 文明、语言、外交、货船舰队仍然不做。
- 不追求戴森球计划那样几十万段传送带的规模，以 MC 服务器的实际性能为准。
- 不使用两款原作的美术、音效和商标，只借鉴玩法。

## 5. 核心玩法循环

- 几分钟：探索、采集、扫描 → 制作、搭建 → 应对星球危害。
- 一次游戏：搭起新一级产线 → 研究新科技 → 解锁新装备、飞船部件或目的地。
- 长期：为了稀有资源扩张到新星球、新恒星系 → 用物流网络连起来 → 建造戴森球 → 研究宇宙矩阵。

## 6. 成长线概览

| 阶段 | 主要内容 | 新的目的地 |
|---|---|---|
| 0 方块时代 | 原版生存；在主世界找到坠毁的探测器，拿到手记和损坏的多功能工具 | 主世界 |
| 1 电磁 | 风力/火力发电、电力塔、采矿机、传送带、分拣器、电弧熔炉、制造台；电磁矩阵（蓝） | — |
| 2 能量 | 原油和精炼、氢、高能石墨；能量矩阵（红）；外骨骼、第一艘飞船 | 母星的卫星、相邻行星 |
| 3 结构 | 钛、硅等外星资源；结构矩阵（黄）；行星内物流站和运输无人机 | 母星系全部行星 |
| 4 信息 | 处理器、粒子带宽；信息矩阵（紫）；跃迁引擎、星际物流站 | 其他恒星系 |
| 5 引力与戴森球 | 电磁弹射器发射太阳帆组成戴森云，垂直发射井发射火箭建造球壳，射线接收站；引力矩阵（绿）、临界光子 | 中子星、黑洞等特殊天体 |
| 6 宇宙 | 反物质、宇宙矩阵（白）、终局科技 | — |

矩阵等名称是工作名，美术和文本阶段再换成原创名称。玩法细节见 [玩法设计](01-game-design.md)。

## 7. 技术方案概要

| 项目 | 选择 |
|---|---|
| 游戏版本 | Minecraft Java 26.3，跟随最新正式版（[ADR-0001](adr/0001-target-version.md)） |
| 加载器 | NeoForge 26.3.0.86 |
| 语言 | Java 25 |
| 构建 | Gradle 9.2.1 + ModDevGradle 2.0.148 |
| 测试 | JUnit 6（core 纯逻辑）+ NeoForge GameTest（游戏内行为） |
| 可选依赖 | GeckoLib（动画）、JEI、Jade；运行时维度自己实现，参考了 Infiniverse（MIT）的思路 |
| 许可证 | 代码 LGPL-3.0-only，美术资源 CC BY-NC-SA 4.0（[ADR-0002](adr/0002-license.md)） |

架构上的主要决定：

- 纯 Java 核心（`core` 包）和游戏适配层分开（[ADR-0003](adr/0003-core-decoupling.md)）。
- 每颗星球是一个运行时创建的维度，到访时生成，空闲时卸载（[ADR-0004](adr/0004-planets-as-runtime-dimensions.md)，M1 原型 S1 已验证可行）。
- 程序生成的内容全部由种子派生，服务端和客户端各自计算，只同步玩家造成的改变。
- 传送带、电网、物流用数据导向的批量模拟，不让每个方块各自 tick。

详见 [技术架构](02-architecture.md)。

## 9. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 运行时创建维度不是原版提供的功能 | 星球系统的地基 | S1 已验证可行（2026-10-16）；依赖访问转换器开放的两个字段，每次升级 MC 都要确认；遗留问题见 ADR-0004 |
| 26.x 渲染管线新、资料少，和 Iris 光影的兼容性未知 | 天空、星球、戴森球的视觉 | M1 做原型并实测 Iris；渲染代码集中在 `client` 包；准备简化版退路 |
| 大规模工厂的性能 | 玩家体验和服务器负载 | 数据导向的模拟；M1 做基准测试；定期用 Spark 剖析；设定性能预算 |
| 跟随最新版的移植成本 | 每个版本都要升级一次 | 核心逻辑和 MC 解耦；新版正式发布后 2–4 周内跟进；必要时停在某个长期版本 |
| 范围过大，单人开发失控 | 项目烂尾 | 里程碑都有退出标准；先做垂直切片；守住非目标清单；每个里程碑结束时复盘 |
| AI 助手对 26.x API 了解有限 | 代码返工 | 写代码前先查反编译源码和 NeoForge 文档；在 CLAUDE.md 里积累 API 备忘 |
| 美术量大（飞船、机器、生物） | 进度和观感 | 先用占位美术；用程序化着色放大变化；Blockbench 建模；后期可以招募美术 |
| 知识产权 | 被要求下架 | 只借鉴玩法；名称、美术、音效全部原创；对外描述不使用原作商标 |
| 多人同步的数据量（戴森球、物流） | 卡顿、不同步 | 种子派生加增量同步；按恒星系订阅；服务端权威 |
| 存档兼容 | 玩家流失 | 存档数据带版本号和迁移；Alpha 之前不保证兼容，并明确告知 |

## 10. 待决问题

- 研究进度按玩家、队伍还是全服共享？倾向默认全服共享，可配置为按队伍。
- 未加载区块里的工厂怎么运行？倾向先用"基地核心"强制加载区块，之后再研究抽象模拟。
- 星团默认有多少个恒星系？倾向 64 个，可配置。
- 中文正式名是否定为"寰宇"？
- 什么时候公开仓库、接受外部贡献？倾向 M2 之后。
